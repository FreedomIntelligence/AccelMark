# Arithmetic-Intensity Profiling Results

This directory contains roofline profiling outputs generated by
`tools/profile_intensity.py`. Each file captures the measured or
analytically-computed arithmetic intensity for a specific (chip, suite) pair
at the suite's benchmark operating point.

## Tool

```
python tools/profile_intensity.py \
    --suite suite_A \
    --model meta-llama/Llama-3-8B \
    --batch 32 --prompt-len 280 --gen-len 128 \
    --dtype bfloat16 \
    --out results/profiling/<chip>_<suite>_intensity.json
```

Defaults for `--batch`, `--prompt-len`, `--gen-len`, and `--dtype` are read
from the suite JSON; CLI flags override them. For chips not in the built-in
peak-spec table, pass `--peak-tflops` and `--peak-bw-gbps`.

## Paper mapping

These profiling runs provide measured intensity anchors for the three
reversal cycles discussed in Appendix B of the AccelMark paper:

| Cycle    | Configs (chip × suite)                           | Classification  |
|----------|--------------------------------------------------|-----------------|
| Cycle 1  | RTX 5090 / A100-80GB × suite_A, suite_D          | Type II-c       |
| Cycle 2  | A100-40GB / H20-3e × suite_A, suite_G            | Type II-b / I   |
| Cycle 3  | RTX 5090 / A100-40GB × suite_A                   | Type II-a       |

Each cycle tests a specific hypothesis about how arithmetic intensity
determines whether a workload is compute-bound or bandwidth-bound, which
in turn governs the effectiveness of chip-level architectural differences.

## Output schema

See the `profile_intensity.py` docstring and the JSON output for the
canonical schema. Key fields per phase:

- `flops` — total floating-point operations
- `bytes` — estimated data movement (HBM)
- `arithmetic_intensity` — FLOPs / bytes
- `achieved_tflops` / `achieved_bw_gbps` — measured rates
- `flops_method` — `"measured"` (FlopCounterMode) or `"analytical"`
- `bytes_method` — `"modelled"` (weight + KV-cache footprint)

The classification (`compute-bound` / `bandwidth-bound`) is derived by
comparing each phase's arithmetic intensity against the chip's roofline
ridge point I* = peak_TFLOPS × 1e12 / (peak_BW_GBps × 1e9).
